# Comandos

| Comando | Qué hace |
|---|---|
| `npm run validate` | **Red de seguridad.** Coherencia `park.json ↔ manifest.json ↔ geojson`, integridad especie↔hábitat, contadores, coordenadas, licencias de foto, transcripciones y presupuesto offline. Bloquea el commit |
| `npm run taxones:duplicados` | El mismo taxón con dos nombres científicos. Sale con código 1 mientras queden. Trae además una tercera pasada por **epíteto dentro de la misma familia**, para los duplicados que no comparten ningún identificador; es sospecha, no veredicto, y no bloquea |
| `npm run taxones:nomenclatura` | **El taxón que está una sola vez y con el nombre equivocado**, que es el punto ciego del anterior: sin duplicado no hay nada que comparar. Sin argumentos hace solo la pasada barata —el género del `scientificName` contra `taxonomy.genus`, que viene de EIDOS— y sale con 1 si discrepan. `--online` pregunta a EIDOS por el nombre y el rango del `eidosTaxonId`, y a GBIF por la key (con caché en `out/`; son ~2.300 peticiones). `--write` corrige **solo lo que no cambia el nombre**; los renombrados los enumera en `Docs/nomenclatura-autoridades.md`, porque desenganchan el texto y hay que decidir entre renombrar y fusionar |
| `npm run taxones:identificadores` | El **mismo taxón con dos claves externas distintas** según el espacio, y la `gbifSpeciesKey` de rango familia o género, que no identifica ninguna especie. Es el fix con las decisiones escritas de la deuda nº 4: cada caso lleva en la cabecera la respuesta de la autoridad. `--write --sql <ruta>` escribe los park.json y los `UPDATE`. **No rellena nulos**: solo sustituye lo que está en conflicto |
| `npm run especies:listaroja` | Rellena `iucnSpain` —la **Lista Roja española**, ámbito España de EIDOS— en el catálogo universal. Sin `--write` solo informa. Un taxón sin esa fila se queda **sin el campo**, no con un «No evaluada» inventado, y un nombre que EIDOS da por sinónimo **no se toca** (eso es la deuda nº 36). Caché en `out/`; después hace falta `npm run species:apply` y, antes del SQL, `Database/migrations.sql` |
| `npm run especies:listaroja-mundial` | Pone `iucnGlobal` en la nomenclatura de `lib/uicn.js` **sin borrar lo que la fuente no desmiente**. A diferencia de su hermano, este campo **ya está escrito en las 1.058 fichas**, así que clasifica en cuatro: **A** redacción (EIDOS confirma la categoría) y **D** hueco (la ficha ya dice «no evaluada») se reescriben; **B** categoría distinta solo con `--con-categoria`, porque cambia lo que la ficha afirma; y **C**, la guarda, **no se toca**: EIDOS callando no dice que no. Caché en `out/`; después, `npm run species:apply` |
| `npm run especies:taxonomia` | Rellena los rangos vacíos de `taxonomy` desde EIDOS (`v_taxonomia`). **Solo rellena huecos: nunca pisa un rango que ya tiene valor** — si EIDOS discrepa ahí, no es un hueco sino que el `eidosTaxonId` apunta a otro taxón, y eso se decide en `taxones:nomenclatura`. Un nombre que EIDOS da por sinónimo no se resuelve. Después, `npm run species:apply` |
| `npm run glossary:check` | Vocabulario científico de las fichas sin definición en el glosario |
| `npm run species:check / :extract / :apply` | Catálogo universal: informar / volcar / sincronizar a todos los espacios (+ SQL) |
| `npm run species:poda` | `:extract` que además **retira** las entradas del catálogo que ya no usa ningún parque (nombres que dejó atrás un renombrado). Sin él solo se listan |
| `npm run habitats:build / :merge` | Capa 2 desde la cartografía del MITECO |
| `npm run atlas:hic -- --atlas <a.txt[,b.txt]> --park <slug> [--json <ruta>] [--fusiona]` | Especies características por HIC desde el Atlas, **cruzadas con el catálogo ya escrito**. Es un paso posterior a la Capa 3: en un espacio sin especies da 0 por construcción. Admite **varios textos** y `--fusiona` conserva lo que ya hubiera en el índice: de qué extractor de PDF salga el `atlas.txt` cambia qué enlaces se leen y **ninguno cubre al otro**, así que el Atlas se usa **solo en positivo** |
| `npm run atlas:aplica [-- --park <slug>] [--write]` | **Tiende en los `park.json` los enlaces que el Atlas respalda** y que solo estaban en `out/<slug>-hic-especies.json`. Solo SUMA —nunca retira— y mantiene el espejo `habitats[].speciesIds`. Idempotente. Un espacio **sin índice del Atlas no se toca** y lo dice: ausente no es cero. Después basta con `park:sql`, sin borrado, porque aquí no desaparece ningún vínculo |
| `npm run sitio:especies -- --park <slug>` | La lista **oficial** de especies de los sitios Red Natura 2000 del espacio (secciones 3.2 y 3.3 del Formulario Normalizado de Datos, IEPNB) → `out/<slug>-rn2000-sitio.json`. **Va antes de `species:seleccion`**: es la puerta de las aves |
| `npm run species:seleccion -- --park <slug> --atlas <a.txt[,b.txt]>` | **La lista aprobada** que consume `species:build` → `out/<slug>-seleccion-especies.json` + informe. Aplica el **orden de prioridad de las fuentes** (regla nº 3 del `CLAUDE.md`): nivel 1 legislación —anexo normativo y formulario del sitio— que entra sin exigir GBIF; nivel 2 EIDOS y Atlas, que necesitan que GBIF los corrobore dentro de los polígonos; nivel 3 solo GBIF, que **no entra**. Más autoctonía, **respaldo de sitio en las aves**, alcance taxonómico y **reconciliación por `eidosTaxonId`**, que impide que el sinónimo y el nombre aceptado de GBIF entren como dos especies. `--gbif-sin-respaldo` levanta el nivel 3 (es el criterio de antes del 2026-08-16); `--clases`, `--todas-las-clases`, `--min-occ`, `--min-habitats`, `--aves-sin-respaldo`. **`--atlas` admite VARIOS textos separados por coma y, además, lee siempre el índice versionado `out/<slug>-hic-especies.json`**: ningún extractor de PDF cubre al otro y `fuentes/atlas.txt` **no es reproducible** (deuda nº 42), así que leer uno solo le quita fichas al espacio con un motivo falso al lado. Se suman y no se restan nunca; `--sin-indice-atlas` desactiva el índice y es solo para comprobar qué aporta un texto por sí mismo |
| `npm run species:build -- --park <slug> [--dry] [--podar]` | **Capa 3**: escribe las fichas de especie en `park.json` desde la selección aprobada. Ensambla lo que ya hay en el repo; no sale a la red. Idempotente. `--podar` retira las fichas que la selección ya no respalda —hace falta tras un renombrado, o el nombre viejo se queda como especie fantasma— |
| `npm run aves:poda -- --park <slug> [--write] [--sql]` | Aplica **solo** el filtro 3 bis (respaldo de sitio en las aves) a un `park.json` **ya escrito**, sin volver a derivar el resto del catálogo → informe en `out/<slug>-poda-aves.md`. Es lo que se usa en un espacio ya publicado; para uno nuevo el filtro va dentro de `species:seleccion`. Sin `--write` no escribe; `--sql` añade el borrado para la BD en `Database/poda-aves-<slug>.sql`, que hace falta porque `park:sql` **solo hace UPSERT y no retira nada**. Idempotente. Se niega a correr si el espacio no tiene ni volcado de sitio ni anexo, que es cuando se llevaría todas las aves por delante |
| `npm run auditoria:consolida -- [--pendientes] [--json <ruta>]` | **La lista de trabajo de la auditoría del catálogo**: los 2.159 hallazgos deduplicados por taxón+campo (**733 correcciones distintas**), ordenados por alcance y repartidos en las colas que no se ejecutan igual, con el estado de cada uno cotejado contra el `park.json` de hoy. Sin red y sin BD. Informe en `Docs/auditoria-consolidado.md`; `--pendientes` deja fuera lo ya hecho, que es la vista útil para trabajar |
| `npm run especies:exclusiones -- [--park <slug>] [--write] [--sql auto]` | **Retira de los `park.json` las fichas que `data/exclusiones-especies.json` da por excluidas.** Ese fichero lo lee `species:seleccion`, que es la puerta de lo que ENTRA: una exclusión escrita DESPUÉS de publicar el espacio no retira nada y nadie avisa —la *Posidonia oceanica* de San Pedro estuvo excluida y publicada a la vez dieciséis días—. Sin `--park` recorre los tres espacios con exclusiones, que es como se comprueba que las ya ejecutadas siguen ejecutadas. `--sql auto` escribe `Database/poda-exclusiones-<slug>.sql` con el motivo dentro y un SELECT que avisa de las `observations` que se llevaría la cascada. Idempotente |
| `npm run aves:fenologia -- [--park <slug>] [--write] [--online]` | Escribe `migratory` y `sitePresence` en las aves ya fichadas, leyendo el `out/<slug>-rn2000-sitio.json` que ya está en el repo en vez de rehacer la Capa 3. Es lo que alimenta la pestaña **«Migratorias»** de la app. Sin `--write` no toca nada; idempotente; las entradas del formulario que no casan por nombre **salen listadas**, nunca adivinadas. Un espacio sin volcado de sitio **no se toca** (y lo dice), en vez de quedarse sin fenología. **`--online` hace la capa 2 del puente** —resolver contra EIDOS el nombre de la FUENTE, con caché en `out/fenologia-eidos-fuente-cache.json`—, que es lo que cierra *Larus ridibundus* → *Chroicocephalus ridibundus*: sin ella quedaban 53 huecos y con ella 29 |
| `npm run taxones:trinomios [-- --park <slug>] [--write] [--sql] [--renombra]` | **Funde la subespecie NOMINAL en su especie** («Phalacrocorax carbo carbo» en *Phalacrocorax carbo*), que es lo que produce dos fichas del mismo bicho cuando el formulario cita en trinomio y el anexo en binomio. Se niega a retirar una ficha que aporte algún dato que la otra no tenga, y lo dice. `--renombra` cubre el trinomio que llega SOLO, sin binomio con el que fundirse. `--sql` deja el borrado en `Database/poda-trinomios-<slug>.sql`, que hace falta porque `park:sql` **solo hace UPSERT**; detrás hay que pasar `species:poda` |
| `npm run especies:ocultar [-- --park <slug>] [--dry] [--mostrar]` | Pone `visible: false` a las fichas **sin descripción**: la app las filtra en vez de servir una ficha en blanco. Son 76 taxones (70 de flora vascular), porque EIDOS no publica el atributo de descripción para la mayoría de las plantas. No borra nada y es idempotente. **Sube la `version` del manifiesto** desde el 2026-09-15: hasta ese día escribía el `park.json` por su cuenta y anunciaba «el manifiesto NO se ha tocado, los contadores no cambian» — y es verdad que no cambian, pero la `version` no habla de contadores, sino de si el dispositivo que tiene el espacio guardado sin conexión vuelve a descargarlo (trampa nº 11). `--mostrar` es el camino de vuelta cuando ya tengan texto |
| `npm run especies:rareza [-- --park <slug>] [--dry] [--destacadas]` | Escribe `rarityLocal` (tramo legal 1–5) leyendo el `spainStatus` y el `murciaStatus` que ya tiene cada ficha. Misma escalera que `species:seleccion` (`Tools/lib/rareza.js`), sin red. Lo que no se puede afirmar queda **sin tramo** en `out/rareza-por-contrastar.md`. `--destacadas` recalcula además `featured`, que por omisión NO se toca |
| `npm run taxones:recombinaciones [-- --write --sql <ruta>]` | Renombra las fichas cuyo nombre EIDOS da por sinónimo **cuando el aceptado es la misma especie en otro género** (deuda nº 36). Ya aplicado el 2026-08-28 sobre 20 de los 48 casos; es idempotente y hoy no cambia nada. Se para si el nombre nuevo ya existe en el espacio: eso es una fusión, no un renombrado |
| `npm run ida-y-vuelta [-- --sql <ruta>]` | **Qué campos del paquete NO tienen columna**, y por tanto desaparecen cuando el paquete se regenera desde la API (deuda nº 3). Lee las claves de los `park.json` y los `geojson` y las compara con las que emiten `park_payload.php` y `park_export.php`. **Sale con código 1** mientras quede una pérdida sin decidir; una pérdida decidida se escribe en `PERDIDAS_ACEPTADAS` con su fecha y su motivo. Sin red ni base de datos |
| `npm run especies:regional [-- --write --sql <ruta>]` | Renombra `murciaStatus` a `regionalStatus` en las fichas ya escritas y les añade `regionalCcaa` desde el `park.region` de su espacio (deuda nº 2). Ya aplicado el 2026-08-27; es idempotente y hoy no cambia nada. **No reescribe el texto** del estado: solo mueve la clave |
| `npm run especies:rareza -- --sql <ruta>` | Escribe los `UPDATE` de los tres campos LOCALES que toca —`rarity_local`, `rarity_local_basis` e `is_featured`—, que **no viajan en el `species-universal.sql`** de `species:apply`. Sin esto, la única vía era regenerar el `-n2.sql` del espacio, que reescribe la ficha entera desde la selección aprobada (trampa nº 6). `is_featured` solo se incluye con `--destacadas` |
| `npm run especies:rareza -- --catalogo` | El otro tramo: migra el `rarityScore` del **catálogo universal** desde su `spainStatus` (solo ámbito estatal, que es lo único universal). Después hace falta `npm run species:apply` para bajarlo a los park.json y al SQL |
| `npm run especies:habitats [-- --park <slug>] [--umbral <n>]` | **Repasa los enlaces especie↔hábitat**, que son el único dato derivado del modelo, contra cuatro cotejos que ya están en el repo: el medio del código HIC frente al que declara la ficha (`Tools/lib/medios.js`), el vuelo del taxón, las ocurrencias del barrido versionado y el Atlas. Informe en `Docs/auditoria-especie-habitat.md` + JSON con todos los enlaces. **No escribe** sin `--write` |
| `npm run especies:habitats:aplica [-- --sql]` | Lo mismo, aplicando las retiradas: recalcula `speciesIds`, ajusta el recuento de hábitats del `source` y sube la versión del manifiesto. Idempotente. **No toca la BD**: con `--sql` deja el borrado redactado en `Database/enlaces-retirados-<slug>.sql`, que hace falta porque `park:sql` **solo hace UPSERT y no retira nada** |
| `npm run especies:niveles [-- --park <slug>] [--detalle] [--json <ruta>]` | **Mide el reparto por niveles de la puerta del catálogo** (regla nº 3) sobre las fichas visibles ya publicadas: N1 respaldo documental, N2 figura legal o Atlas, N3 solo GBIF. Sin red y solo lectura; la figura legal se lee del texto de la ficha, así que vale para el **delta** con criterio constante, no para compararse con una medición contra EIDOS en vivo. Existe porque esta medición ya se perdió dos veces por vivir solo en informes de sesión |
| `npm run especies:biodiversidad [-- --niveles <ruta>] [--out <ruta>]` | **Agrega hábitats, especies y rareza legal por espacio** sobre los `park.json` ya publicados, para la pestaña «Biodiversidad» de la app y el popup del selector de parque. Sin red, solo lectura, idempotente. Escribe `Frontend/Data/parks-biodiversidad.json`, aparte de cada `park.json` a propósito (ver su cabecera). Si existe `out/niveles-puerta.json` (lo deja `especies:niveles`), añade también el reparto N1/N2/N3 de cada espacio |
| `npm run especies:legal [-- --online] [--park <slug>] [--sin-cache]` | **Coteja contra EIDOS la figura legal que AFIRMA el texto de cada ficha** (deuda nº 43). `spainStatus` y `regionalStatus` son prosa escrita a mano en el piloto, y de ese texto salen dos campos que el usuario ve: el nivel 2 de `especies:niveles` y el `rarityLocal` de `especies:rareza`. Informe en `Docs/cotejo-estado-legal.md`, en siete clases; **no escribe nada** porque la contradicción va en las dos direcciones y resolverla exige ir al BOE y al BORM. **Sin `--online` ya salen tres clases**: el texto que no es un estado legal (D), el que solo cuelga de una evaluación o de una Directiva y por tanto `v_estadolegal` no puede confirmar (F), y el taxón al que dos espacios de la **misma comunidad** dan tramos distintos (G), que no puede ser y que `validate` no ve porque solo coteja entre parques los campos universales |
| `npm run images:species / :habitats / :invasoras` | Fotos con atribución desde Wikimedia |
| `npm run contenido:invasoras` | Fichas de invasoras desde EIDOS |
| `npm run invasoras:eei` | Catálogo EEI ∩ presencia GBIF por territorio |
| `npm run eidos:diff` | Coteja la BD viva contra EIDOS (solo lectura). `-- --ccaa "<comunidad>"` |
| `npm run gbif:habitats` | Ocurrencias GBIF ∩ polígonos de hábitat, con análisis de ruido |
| `npm run pois:build <slug> [--fuente=auto\|overpass\|basemap]` | **Fase 3**: candidatos a punto de interés dentro del límite oficial → `out/<slug>-poi-candidatos.md`. Escribe candidatos, nunca `park.json` |
| `npm run images:pois -- --park <slug> --categoria "<Categoría de Commons>"` | Foto y crédito de cada POI. **Con `--park` reescribe `Database/poi-imagenes.sql` solo con ese espacio**: hay que conservar a mano las sentencias ya aplicadas de los demás |
| `npm run images:pois:alt -- --park <slug>` | Las fotos de POI que Commons no tiene, en Openverse, Flickr, Mapillary, Europeana e iNaturalist → `Docs/fotos-poi-alt.md`. **Todo sale «a revisar» y no escribe nada** sin `--write --force`. Claves por entorno: `FLICKR_API_KEY`, `MAPILLARY_TOKEN`, `EUROPEANA_WSKEY` |
| `npm run pois:sql -- --park <slug>` | Vuelca el bloque `pointsOfInterest` de un `park.json` a SQL idempotente → `Database/n3-pois-<slug>.sql`. **La API manda sobre el paquete**: sin aplicarlo, el espacio se sirve con 0 POIs |
| `npm run park:sql -- --park <slug>` | Vuelca el **N2 completo** —fila de `parks`, hábitats con geometría, especies y vínculos— → `Database/<slug>-n2.sql`. **Va antes que `pois:sql`**: sin fila en `parks`, todo lo demás carga cero filas en silencio |
| `npm run tiles:build <slug>` | Paquete de mapa base offline |
| `npm run trails:build <slug>` | Senderos señalizados (GR, PR, SL) que pasan por el parque |
| `npm run tiempo:municipios [-- --write --sql Database/parks-tiempo.sql]` | **El municipio de referencia de cada espacio para la predicción de AEMET, con su código INE.** Sin `--write` solo informa. Necesita `AEMET_API_KEY` en el entorno (`--cache` reutiliza el maestro ya descargado y no la necesita). **La API manda sobre el paquete**: sin aplicar el `--sql`, un despliegue con backend no pinta el widget del tiempo aunque el código esté en el repositorio. Lo que no case se queda **sin código y sin widget**, enumerado al final |
| `npm run export:park / :glossary / :invasoras` | Regenera los JSON empaquetados desde la BD |
| `npm run export:dwc` | **Darwin Core Archive** de los avistamientos (`occurrence.txt` + `meta.xml` + `eml.xml`). Solo salen los usuarios que han dado su consentimiento, y las coordenadas de los taxones amenazados salen generalizadas. `-- --usuario <id\|correo>`, `-- --salida <ruta>`, `-- --zip`. Ver [DARWIN-CORE.md](DARWIN-CORE.md) |
| `npm run db:status / :pull / :push / :backup` | Sincronización con el MySQL del contenedor |
| `node Tools/dev-server.js [--puerto 8000]` | Sirve `Frontend/` por HTTP para **mirar la app sin PHP instalado**. Con `file://` no arranca: el navegador bloquea los módulos ES. **No sustituye a `php -S localhost:8000 -t .`**, que es la receta del repo (`.claude/launch.json`): no sirve `Backend/Api/`, así que la app cae al `park.json` empaquetado — lo mismo que ve un dispositivo sin cobertura |

Ninguna herramienta de Capa 2/3 escribe en la BD ni en el seed directamente (salvo
`enrich-images.js --write-park`, documentado en su cabecera): generan ficheros en `out/` para revisar
antes de adoptarlos.
